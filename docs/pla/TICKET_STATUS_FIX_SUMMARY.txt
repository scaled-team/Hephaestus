ISSUE
───────────────────────────────────────────────────────────────────────────────

User Report: "tickets do not seem to be moving throught the ohases as the agent
works oniy it should update the kaban board so we know the current status"

Root Cause: Frontend KanbanBoard component was NOT listening for
            'ticket_status_changed' WebSocket events from backend.

Impact:     Kanban board showed stale ticket positions; users couldn't see
            real-time progress as agents worked on tasks.

───────────────────────────────────────────────────────────────────────────────
SOLUTION
───────────────────────────────────────────────────────────────────────────────

File Modified:    frontend/src/components/tickets/KanbanBoard.tsx
Lines Changed:    +13 lines (added missing listener)
Complexity:       MINIMAL - Just adding one missing listener

Code Added (lines 54-57):
────────────────────────────────────────────────────────────────────────────────
  const unsubscribeStatusChanged = subscribe('ticket_status_changed', (data) => {
    queryClient.invalidateQueries({ queryKey: ['tickets', workflowId] });
    queryClient.invalidateQueries({ queryKey: ['ticketStats', workflowId] });
  });
────────────────────────────────────────────────────────────────────────────────

Cleanup Added (line 64):
  unsubscribeStatusChanged();

How It Works:
1. Backend broadcasts 'ticket_status_changed' event when agent updates task
2. Frontend listener receives the event
3. React Query caches are invalidated
4. Kanban board automatically refetches and updates
5. User sees real-time ticket movement between columns
